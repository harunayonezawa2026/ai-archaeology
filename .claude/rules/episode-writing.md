# AI考古学 エピソード執筆ルール

新規エピソードを書くときは、このファイルを参照してから着手する。

---

## 必須テンプレート

`content/notes/_episode-template.mdx` をコピーして新しいエピソードを作る。
テンプレートの `[placeholder]` を全部埋めてからデプロイする。

---

## 禁止ワード（使ったら即差し替え）

| 禁止 | 代わりに使う |
|---|---|
| 直系の祖先 | 重要な前史 / 問題意識の先行例 |
| 完全に同型 / 完全に一致 | 問題意識が重なっている / 設計として似た課題を扱っている |
| 証明している | 再評価する補助線になる / 問題意識の共通性を示している |
| 誰も読んでいない | 一般の技術語りでは参照されにくい |
| AIを殺した | 研究予算の流れを大きく変えた / 研究の○年を止めた |
| 一夜で枯らした / 即座に消えた | 大幅に削減させる根拠になった |
| 全く同じ問題 | 驚くほど似た問題設定 |

**判断基準**：「これを言い切るには、どんな一次資料が必要か？」を自分に問う。
証拠の要求水準を超える言葉は全部禁止ワードになり得る。

## 対応表を作った後に必ず実行するプロンプト

```
上の対応表の各行について：
1. 「同一」— 設計・実装レベルで実際に一致している
2. 「類似」— 問題意識は共通、実装・設計は異なる
3. 「比喩」— 概念的に似ているが、技術的には別物
4. 「無理がある」— 対応として強引、専門家から突っ込まれやすい

4段階で評価してください。
さらに、その分野の研究者・エンジニアから想定される具体的な反論を
（「それは違う、なぜなら…」という形で）各行に1〜2文で列挙してください。
```

このプロンプトなしで対応表を記事に載せない。

---

## 「厳密にはこう」欄の必須5項目

記事末（参考リンクの直前）に必ず入れる：

1. **確認済みの事実** — 1次資料で確認した事実のみ。取得URL・文書名を明記
2. **著者の解釈** — 「前史」「問題意識の重複」と言っている部分の根拠を示す
3. **比喩・アナロジー** — 対応表のうち「比喩・類比」レベルの行を列挙
4. **未確認** — Forward citations・有料文書・内部資料など今回取得していないもの
5. **この比較が破綻する点** — 専門家から最初に突っ込まれるポイントを先に書く

## 一次資料の到達状況を正直に書く

| 状況 | 書き方 |
|---|---|
| フルテキスト取得成功 | 「Google Patentsからフルテキストを取得し、Claudeに読ませた」 |
| Wikipedia経由のみ | 「原文には今回到達できていない（Wikipedia経由の情報）」 |
| PDF取得・OCR未実施 | 「PDF取得済みだがテキスト抽出はOCR未実施」 |
| 有料・未入手 | 「IEEE Xploreで有料（$200）・今回未入手。Wikipedia・業界誌経由の間接情報」 |

発掘ログの信頼性は「一次資料にどこまで届いたか」の正直な開示が支える。
